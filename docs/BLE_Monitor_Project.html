Project Overview

BLE Monitor

BLE Monitor 是一款基于 Flutter 的跨平台蓝牙低功耗（BLE）设备监控应用， 支持 Android、iOS 及 Windows 多端运行。应用能够实时扫描、连接 BLE 设备， 采集电流、电压、功率等传感器数据，提供精细化的功耗分析、历史图表、阈值告警及透传遥控等完整功能， 是面向功耗测量硬件设备的一体化移动管理平台。

Flutter 3.0+ Dart BLE / 蓝牙低功耗 GetX 状态管理 SQLite 持久化 实时功耗监控 跨平台 Android/iOS/Windows 梯形积分法 告警推送 OTA 固件升级 MQTT 协议 GPS 骑行追踪
项目名称: ble_monitor  ·  框架: Flutter 3.0+ / Dart  ·  状态管理: GetX  ·  数据库: SQLite v6  ·  平台: Android · iOS · Windows

数据流向

从 BLE 设备的原始广播包到 UI 展示，数据经历完整的采集→解析→存储→告警→展示流程：

1
BLE 设备广播 — 目标设备通过 BLE 广播包（Advertisement）持续发送制造商自定义数据（Manufacturer Data）
2
平台蓝牙层 — FlutterBluePlus（移动端）或 WinBle（Windows）接收原始扫描结果，通过 BluetoothAdapter 统一封装
3
BleController 处理 — _parseDataPacket() 解析字节流，提取电流值、单位、电压值，构造 DeviceData 对象
4
MonitorController 聚合 — 接收 DeviceData，执行去重（1秒间隔）、频率限制（500ms），维护 SelectedDevice 数据历史
5
DatabaseService 持久化 — 批量写入（10秒间隔）SQLite 数据库，保存时序数据与日/月功耗统计
6
AlertService 告警检查 — 将最新数值与设备配置阈值对比，触发振动 / 声音 / 系统通知
7
UI 响应式更新 — GetX Obx() 监听数据变化，MonitorPage、ChartPage、PowerStatsPage 自动刷新显示

启动流程

应用启动时依次完成权限申请、数据库初始化、服务注册与蓝牙初始化：

1
main() — 调用 WidgetsFlutterBinding.ensureInitialized()，注册全局 GetX 服务
2
DatabaseService.init() — 初始化 SQLite 数据库，执行 Schema 迁移（当前 v6）
3
NotificationService.init() — 初始化本地通知（移动端 flutter_local_notifications，Windows 端 local_notifier）
4
PermissionHelper.requestPermissions() — 申请蓝牙扫描、位置、通知等系统权限
5
BleController.initBluetooth() — 注册蓝牙状态监听，启动首次扫描，加载已保存设备列表
6
MainAppPage 渲染 — 底部三标签导航就绪，扫描健康检查定时器（5秒）开始工作
// main.dart - 服务注册顺序
void main() async {
  WidgetsFlutterBinding.ensureInitialized();

  // 1. 数据库
  await Get.putAsync(() => DatabaseService().init());

  // 2. 通知服务
  final notificationService = NotificationService();
  await notificationService.init();
  Get.put(notificationService);

  // 3. 核心控制器（Permanent - 全应用生命周期）
  Get.put(BleController(),      permanent: true);
  Get.put(MonitorController(),  permanent: true);
  Get.put(AlertService(),       permanent: true);

  runApp(const MyApp());
}

BLE 扫描与连接

应用通过持续 BLE 扫描（不建立 GATT 连接）的方式从广播包中提取传感器数据，低功耗且实时性高。

扫描工作流程

1
initBluetooth() — 注册蓝牙状态监听（开/关），加载已保存设备配置
2
startScan() — 启动连续扫描，扫描间隔由 ScanSettingsService 读取（默认 2 秒，范围 0.5~60s）
3
_processScanResults() — 过滤制造商数据不为空的设备，排除不支持的设备类型
4
_parseDeviceData() — 提取 manufacturerData 字节数组，根据平台选择对应解析逻辑
5
ManufacturerDataParser.parseManufacturerData() — 字节转换为电流/电压数值，构造 DeviceData 对象
6
健康检查定时器（5秒） — 检测扫描是否意外停止，自动重启扫描保障连续性

扫描间隔设置

参数值说明
最小间隔0.5 秒高频场景，耗电较高
默认间隔2 秒平衡功耗与实时性
最大间隔60 秒低频监控，省电模式
数据去重间隔1 秒同一设备相同数据不重复存储
频率限制500 msUI 刷新节流，防止过度渲染

数据包格式

目标设备在 BLE 广播包的制造商数据字段中按自定义协议编码传感器数值，应用针对 Windows 与移动端各自的格式做了差异化解析：

移动端（Android / iOS）格式 — 最少 5 字节

偏移  字节数  字段           说明
----  ------  ------         -------
0     1       电流高字节      与 Byte[1] 共同组成 16-bit 电流原始值
1     1       电流低字节      Little-Endian，高字节在 [1]
2     1       电流单位        1=nA / 10=uA / 50=mA / 100=A
3     1       电压高字节      与 Byte[4] 共同组成 16-bit 电压原始值（单位 mV）
4     1       电压低字节      Little-Endian，高字节在 [4]

// 解析示例
int rawCurrent = (bytes[1] << 8) | bytes[0];
int unitCode   = bytes[2];              // 1/10/50/100
int rawVoltage = (bytes[4] << 8) | bytes[3];  // mV

Windows 端格式 — 最少 7 字节

偏移  字节数  字段           说明
----  ------  ------         -------
0     2       设备 ID         Little-Endian 设备标识符
2     1       电流高字节
3     1       电流低字节      高字节在 [3]
4     1       电流单位        同上
5     1       电压高字节
6     1       电压低字节      高字节在 [6]，单位 mV

// 解析示例（Windows）
int deviceId   = (bytes[1] << 8) | bytes[0];
int rawCurrent = (bytes[3] << 8) | bytes[2];
int rawVoltage = (bytes[6] << 8) | bytes[5];

电流单位换算

单位码单位换算系数适用量程
1nA（纳安）÷ 1,000,000超低功耗设备，μA 以下
10μA（微安）÷ 1,000低功耗 IoT 设备
50mA（毫安）÷ 1一般嵌入式设备
100A（安培）× 1大电流设备
功率计算：P (mW) = (voltage_mV / 1000) × current_mA， 其中 current_mA 为统一换算后的毫安值，voltage 单位为毫伏。

实时监控

MonitorController 负责管理所有已选中设备的实时监控状态，核心功能包括数据接收、去重、存储批处理与功耗积分计算。

SelectedDevice — 单设备监控数据结构

class SelectedDevice {
  final String   deviceId;
  String         deviceName;
  var            isMonitoring;       // Rx<bool> 响应式标志

  // 实时数据历史（最多 86,400 条，约 24 小时 1Hz 采样）
  final List<DeviceData> dataHistory;

  // 功耗追踪（梯形积分法）
  double         _sessionConsumption;        // 本次会话（mAh），应用重启清零
  List<double?>  _dailyConsumptionArray;     // 近 365 天日功耗（mAh）
  List<double?>  _monthlyConsumptionArray;   // 近 12 月月功耗（mAh）

  // 最新读数快速访问
  double get latestCurrent  => dataHistory.last.current;
  double get latestVoltage  => dataHistory.last.voltage;
  double get latestPower    => dataHistory.last.power;
  double get powerConsumption => _sessionConsumption;
}

数据去重与限流策略

策略参数目的
时间间隔去重相邻两条 ≥ 1 秒避免同一时刻重复存储
内容去重连续相同值合并节省存储空间
UI 刷新节流每 500ms 最多刷新一次防止过度重绘造成卡顿
批量入库每 10 秒写一次 SQLite减少磁盘 I/O 压力
历史上限每设备 86,400 条防止内存无限增长
数据库上限每设备 2,592,000 条约 30 天 1Hz 历史数据

功耗统计

应用通过梯形积分法对时序电流数据进行数值积分，得到精确的电量消耗（mAh）：

积分算法

// 梯形积分法计算功耗增量
// 相邻两个采样点 (I1, t1) 和 (I2, t2)
double deltaTime    = (t2 - t1).inMilliseconds / 3600000.0;  // 转换为小时
double avgCurrent   = (I1 + I2) / 2.0;                       // 梯形平均值（mA）
double deltaCharge  = avgCurrent * deltaTime;                 // 增量电量（mAh）

_sessionConsumption += deltaCharge;

多时间维度统计

维度存储结构容量说明
会话功耗_sessionConsumption（double）单值应用每次启动清零，仅统计本次运行
日功耗List<double?> 365 元素365 天按日历日期索引，null 表示无数据
月功耗List<double?> 12 元素12 个月按月份索引（0=1月），累计当月所有日数据
年功耗由月功耗汇总计算实时聚合UI 层对 12 月数据求和展示
日功耗和月功耗数组持久化存储于 SQLite 的 daily_power_consumption 和 monthly_power_consumption 表中，支持跨次启动累计追踪。

连接状态检测
实时监测蓝牙连接状态，断连时自动禁用所有发送按钮，防止无效操作
🔢
手动输入
支持手动输入任意十六进制字符串并发送，灵活应对临时调试需求
遥控页面通过监听 GATT Characteristic 通知实现数据接收，发送指令走 Write Without Response 模式以保证低延迟。

骑行追踪

集成 Geolocator 实现 GPS 实时追踪，记录完整骑行轨迹，适用于绑定了功耗监控设备的自行车/电动车场景：

功能实现方案说明
实时速度geolocator 位置流计算基于相邻 GPS 点距离/时间差计算，m/s 转 km/h 显示
行驶距离Haversine 公式累计球面距离计算，精度约 ±5 米
实时海拔GPS altitude 字段WGS84 椭球高度，误差约 ±10 米
轨迹记录RidePoint 序列存储每秒一个 GPS 点，完整轨迹可回放
历史记录SQLite rides + ride_points可浏览历史骑行数据，查看里程/速度/海拔曲线
仪表盘显示CyclingDashboardPage大字体速度+距离+时间+消耗功耗一体展示
骑行功能当前处于开发完善阶段（git 日志显示近期有骑行界面显示修复），部分功能可能存在边界情况。

OTA 固件升级

OtaUpgradePage 配合 OtaService 实现对已连接 BLE 设备的在线固件升级：

1
文件选择 — 使用 file_picker 从本地存储选择固件 .bin 文件
2
连接检查 — 确认目标设备已通过 GATT 连接，检查升级 Characteristic UUID
3
分包传输 — 按固定包大小分割固件文件，通过 Write Characteristic 逐包发送
4
进度反馈 — UI 实时显示传输百分比与剩余字节数
5
完成确认 — 接收设备返回升级成功/失败通知，提示用户重启设备
OTA 服务同时引入了 dio HTTP 客户端，支持从远程 URL 下载固件文件后升级，可实现云端版本管理。
