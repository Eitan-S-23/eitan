02 · nRF52832 Relay

nRF52832 ANT+BLE 中继模块

⚙模块定位与架构

nRF52832 在系统中充当 三协议桥接节点：

ANT+ 主机（Display Receiver）
以从机/显示器角色接收周边运动传感器的 ANT+ 广播数据
BLE 从机（Peripheral）
向手机 App 提供 GATT 服务，广播周期 25 ms，MTU 247 字节
UART 串口透传（115200 bps）
P0.25（RX）/ P0.26（TX），与 AT32F435 双向互通；帧边界由 10 ms 超时判定，单帧最大 244 字节
Nordic nRF5 SDK SoftDevice 双栈 UART 115200 bps Keil / SES

💻PC 端：bsdiff 制包工具

读取旧固件与新固件，输出 patch_encrypt.bin，体积通常为新固件的 10~30%。

bsdiff 差分算法
生成三段差分块（控制块、差分块、附加块）
LZMA 压缩
lc=2 lp=0 pb=0 fb=64 dict=4KB；多线程编码（LzFindMt），MCU 端单线程解压
CRC32 构建补丁头
含旧固件 CRC、新固件 CRC、文件大小、LZMA 属性（共 37 字节头部）
AES-128-CTR 加密
随机 12 字节 Nonce + 4 字节计数器组成 16 字节 IV，流式加密，输出 patch_encrypt.bin
bsdiff 差分 LZMA 7-Zip SDK AES-128 CTR CMake / Windows GUI

🔃码表端：bspatch 升级执行

码表运行于 app1 或 app2 分区时均可响应升级，补丁存储于 W25Q128 QSPI Flash。

从 W25Q128 读取差分包
虚拟文件系统适配层，可替换为 SD 卡等存储
AES-128-CTR 流式解密
提取首 16 字节 Nonce+Counter，边读边解，最小化 RAM 占用
校验补丁头 CRC32
验证头部完整性，比对旧固件 CRC 确认版本匹配
LZMA 流式解压 + bspatch
LzmaDec 单线程解压；基于旧固件逐块重建新固件，EraseAndWriteFlash() 写入目标分区
新固件 CRC32 校验
校验通过后写 AT24C02 更新启动标志；校验失败则保留旧分区，安全回退
重启 → Bootloader 选分区
读取 AT24C02 标志，跳转新固件地址运行
流式处理 低内存占用 双分区 app1/app2 CRC32 三重校验 平台无关 HAL

💾AT24C02 EEPROM — OTA 状态与分区管理

AT24C02 挂载于 I2C 总线（地址 0x50，SDA=PB7，SCL=PB6），容量 256 字节，掉电不丢失，专用于存储 OTA 过程中的关键元数据：

  • 当前活跃运行分区（app1 / app2）
  • 升级状态标志（空闲 / 升级中 / 待切换）
  • 新固件版本信息及 CRC
  • 错误码与升级计数（便于调试回溯）
💡
Bootloader 上电后首先读取 AT24C02，根据分区标志决定跳转 app1 还是 app2；若新固件 CRC 校验失败则自动回退至旧分区，保障设备在升级异常时仍可正常启动。

AT24C02 典型地址布局（示意）

/* AT24C02 OTA 状态区（256 字节）*/
#define EEPROM_ADDR_BOOT_FLAG   0x00
  // 0x01 = 运行 app1
  // 0x02 = 运行 app2
  // 0xAA = 升级完成，待切换

#define EEPROM_ADDR_OTA_STATUS  0x01
  // 0x00 = 空闲
  // 0x01 = 接收差分包中
  // 0x02 = bspatch 执行中

#define EEPROM_ADDR_NEW_VER     0x10
#define EEPROM_ADDR_NEW_CRC     0x14
#define EEPROM_ADDR_ERR_CODE    0x20
#define EEPROM_ADDR_UPGRADE_CNT 0x24

（具体字段以实际代码为准，此处为示意布局）

📋差分包头部格式（patch_header_t）

typedef struct patch_header {
    uint32_t ph_hcrc;           // 头部 CRC32（大端）
    uint32_t ph_psize;          // 压缩后差分包大小（大端）
    uint32_t ph_osize;          // 旧固件大小（小端）
    uint32_t ph_nsize;          // 新固件大小（小端）
    uint32_t ph_ocrc;           // 旧固件 CRC32（大端）— 版本匹配验证
    uint32_t ph_ncrc;           // 新固件 CRC32（大端）— 升级成功验证
    uint8_t  ph_lzma_props[5]; // LZMA 属性字节（lc/lp/pb/dict）
    uint64_t ph_original_size;  // 解压前差分数据原始大小
} patch_header_t;               // AES 加密前写入，Nonce(16B) + Header + 压缩数据

📅实时骑行数据全链路

ANT+ 传感器广播（~250 ms / 次）
nRF52832 ANT+ 主机接收 HRM 等 Profile 数据
nRF52832 双路输出
① 心率值经 BLE HRS（0x180D）直接 Notify 手机；② 全部数据经 UART（115200 bps）转发给 AT32F435
AT32F435 DataProc 融合处理
DP_Power 计算均值/NP；DP_GPS 更新位置；DP_IMU 辅助航向；DP_Recorder 追加 GPX 轨迹点至 SD 卡
LVGL UI 刷新
仪表盘数字 500 ms 刷新；LiveMap 30 ms 渲染位置标记
AT32F435 → UART → nRF52832 → BLE → 手机 App
打包后骑行数据（功率、速度、GPS、踏频）经 0xFFF1 Notify 推送，约 1 Hz
App 持久化 & 可视化
MonitorController 写 SQLite；fl_chart 实时更新；功率区间数组按日累计

⚡功率统计持久化

App 维护 Z1~Z7 七个功率区间的时间数组，每秒在对应区间累加；骑行结束后批量写入 SQLite power_stats 表，支持日/周维度图表渲染。

区间数组 Z1~Z7 sqflite 批量写入 SharedPreferences 缓存

💾SD 卡 GPX 轨迹录制

DP_Recorder 以 GPX 格式将时间戳、经纬度、海拔、心率、功率写入 SD 卡；USB MSC 模式下码表被识别为 U 盘，可直接导出 .gpx 至 Strava 等平台。
