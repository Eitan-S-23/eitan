Project Overview

nRF52832 BLE / ANT+ 双协议中继器

本项目是基于 Nordic Semiconductor nRF52832 芯片的嵌入式固件，实现了 BLE（蓝牙低功耗）、ANT+ 无线协议与 UART 串口的三路双向数据中继网关。 核心应用场景为将 ANT+ 心率传感器数据桥接至 BLE 中央设备，同时提供 自定义 BLE UART 服务，实现串口与蓝牙的透明双向转发。

nRF52832 ARM Cortex-M4F BLE 5.x + ANT+ S312 双协议 SoftDevice ANT HRM 接收 BLE UART 透传 心率服务 HRS UART 115200 bps 事件驱动架构 GCC ARM 工具链
芯片: nRF52832-XXAA  ·  SoftDevice: S312 v6.1.x  ·  SDK: nRF5 SDK v17.1.0  ·  Flash: 512 KB  ·  RAM: 64 KB  ·  CPU: 64 MHz

BLE → UART 转发路径

1
BLE 中央写入 — 手机 App 写入自定义 UART RX 特征值（UUID: 0xFFF1）
2
BLE 事件回调 — ble_evt_handler() 捕获 BLE_GATTS_EVT_WRITE 事件
3
UART 发送 — 调用 app_uart_put() 逐字节写入 UART TX 队列
4
串口输出 — UART 硬件以 115200 bps 将数据发送至外部串口设备

UART → BLE 转发路径

1
UART 中断接收 — uart_event_handler() 将字节存入 733 字节软件环形缓冲区
2
帧超时检测 — 10 ms 无新数据时，App Timer 触发帧完成标志
3
主循环轮询 — 主循环检测帧就绪，从缓冲区读取最多 244 字节
4
BLE 发送 — 调用 ble_uart_data_send()，通过 TX 特征值通知发送至中央设备
5
回显确认 — 数据同时回显至 UART 输出，便于调试确认

初始化流程

main() 函数按严格顺序执行 10 步初始化，确保硬件、协议栈、服务依次就绪：

1
timers_init()
初始化 App Timer 模块，创建帧超时定时器（10 ms 单次触发），用于 UART 帧边界检测。
2
power_management_init()
初始化 nRF 电源管理模块，配置低功耗休眠策略（WFE/WFI 指令），注册系统状态监控回调。
3
softdevice_setup()
启用 S312 SoftDevice，配置 BLE + ANT 双栈 RAM 分配。调用 nrf_sdh_enable_request() 激活无线射频。
4
bsp_init()
板级支持包初始化，配置 LED 指示灯和按键（PCA10040 开发板），注册 BSP 事件回调。
5
gap_params_init() + gatt_init()
设置 GAP 参数：设备名称 "Nordic_HRM"，外观 Heart Rate Sensor (Belt)，连接间隔 50–100 ms，从机延迟 0。初始化 GATT 模块，请求 MTU 247 字节（有效载荷 244 B）。
6
services_init()
依次注册三个 GATT 服务：心率服务 (HRS)、设备信息服务 (DIS)、自定义 UART 服务（UUID 0xFFF0）。
7
advertising_init() + conn_params_init()
配置广播包（间隔 25 ms，包含 HRS + UART UUID），初始化连接参数协商模块（最大重试 3 次）。
8
uart_init()
配置 UART：TX P0.26 / RX P0.25，波特率 115200，无流控，无奇偶校验。硬件 FIFO 512 B，软件环形缓冲区 733 B。
9
ant_hrm_rx_init()
初始化 ANT Channel 0 为 HRM 接收模式，设备号/传输类型均为 0（通配符，接受任意 ANT+ 心率带）。
10
advertising_start()
启动 BLE 广播，同时打开 ANT 信道，设备进入就绪状态，等待 BLE 中央设备连接和 ANT+ 传感器配对。

自定义 UART 服务实现

UART 服务使用 128-bit 基础 UUID 派生出三个特征值，代码直接向 GATT 服务器注册属性：

// main.c — 自定义 UART 服务结构体
typedef struct {
    uint16_t             service_handle;   // GATT 服务句柄
    ble_gatts_char_handles_t tx_handles;   // TX 特征值（Notify）
    ble_gatts_char_handles_t rx_handles;   // RX 特征值（Write）
    uint8_t              uuid_type;        // UUID 类型（厂商自定义）
} ble_uart_service_t;

// 服务 UUID: 0xFFF0（16-bit 短 UUID）
#define BLE_UUID_UART_SERVICE  0xFFF0
#define BLE_UUID_UART_TX_CHAR  0xFFF2   // 通知特征（设备→手机）
#define BLE_UUID_UART_RX_CHAR  0xFFF1   // 写入特征（手机→设备）

// 发送函数：通过 BLE 通知将数据推送至中央设备
static void ble_uart_data_send(uint8_t *p_data, uint16_t length) {
    ble_gatts_hvx_params_t hvx_params;
    memset(&hvx_params, 0, sizeof(hvx_params));
    hvx_params.handle = m_uart_service.tx_handles.value_handle;
    hvx_params.type   = BLE_GATT_HVX_NOTIFICATION;
    hvx_params.p_len  = &length;
    hvx_params.p_data = p_data;
    sd_ble_gatts_hvx(m_conn_handle, &hvx_params);
}

// main.c — ANT HRM 事件处理器
void ant_hrm_evt_handler(ant_hrm_profile_t * p_profile,
                         ant_hrm_evt_t        event)
{
    switch (event) {
        case ANT_HRM_PAGE_0_UPDATED:
            // 从 Page 0 获取心率值并通过 BLE HRS 上报
            err_code = ble_hrs_heart_rate_measurement_send(
                &m_hrs,
                p_profile->page_0.computed_heart_rate);
            break;

        case ANT_HRM_PAGE_4_UPDATED:
            // 从 Page 4 获取 R-R 间期（心跳间隔时间，单位 1/1024 s）
            err_code = ble_hrs_rr_interval_add(
                &m_hrs,
                p_profile->page_4.beat_interval);
            break;

        default:
            break;
    }
}
设备号和传输类型均设置为 0（通配符），可自动配对任意品牌的 ANT+ 心率带（Garmin、Polar、Wahoo 等），无需预先配置。

缓冲区设计

为实现无阻塞的 UART-BLE 数据转发，项目采用三级缓冲策略：

硬件 FIFO
RX FIFO: 512 B TX FIFO: 512 B nRFx UART 驱动 中断驱动
软件环形缓冲
733 字节 ISR → 应用层 uart_event_handler 写入 主循环读取
BLE 发送帧
最大 244 字节/帧 MTU 247 - 3 ATT 头 每次循环最多 10 包 sd_ble_gatts_hvx 发送 
// main.c — 软件环形缓冲区（733 字节）及帧就绪标志
#define UART_BUFFER_SIZE    733
static uint8_t  m_uart_rx_buffer[UART_BUFFER_SIZE];
static uint16_t m_uart_rx_head   = 0;
static uint16_t m_uart_rx_tail   = 0;
static bool     m_uart_frame_rdy = false;  // 帧就绪标志

// 帧超时回调（10 ms App Timer）
static void uart_timeout_handler(void * p_context) {
    if (m_uart_rx_head != m_uart_rx_tail) {
        m_uart_frame_rdy = true;   // 标记帧完成，主循环处理
    }
}

// 主循环：处理就绪帧并分批发送 BLE 通知
while (true) {
    if (m_uart_frame_rdy) {
        m_uart_frame_rdy = false;
        uint8_t  pkt[244];
        uint16_t len = 0;
        uint8_t  pkt_cnt = 0;

        while (ring_buf_read(pkt, &len, 244) && pkt_cnt < 10) {
            ble_uart_data_send(pkt, len);  // 发送 BLE 通知
            // 同时回显至 UART
            for (uint16_t i = 0; i < len; i++) app_uart_put(pkt[i]);
            pkt_cnt++;
        }
    }
    nrf_pwr_mgmt_run();  // 无事件时进入低功耗休眠
}

双向数据转发机制

关键设计决策

⏱
帧超时检测
10 ms 无新字节即认为一帧完成，适合大多数串口协议帧间隔，无需预知帧格式或长度字段。
🔄
非阻塞设计
每次主循环最多处理 10 包（2440 B），防止单次 BLE 发送占用过长时间，保持系统响应性。
📦
MTU 分片
BLE MTU 247 B，有效载荷 244 B。超过 244 B 的 UART 帧自动分片为多包 BLE 通知发送。
🔁
UART 回显
BLE 发送的数据同时回显至 UART，便于调试确认数据完整性，也可用于环路测试。

BLE 事件处理器核心逻辑

// main.c — BLE 事件分发（简化）
static void ble_evt_handler(ble_evt_t const * p_ble_evt, void * p_context) {
    switch (p_ble_evt->header.evt_id) {

        case BLE_GAP_EVT_CONNECTED:
            m_conn_handle = p_ble_evt->evt.gap_evt.conn_handle;
            // BSP LED 指示连接状态
            bsp_indication_set(BSP_INDICATE_CONNECTED);
            break;

        case BLE_GAP_EVT_DISCONNECTED:
            m_conn_handle = BLE_CONN_HANDLE_INVALID;
            // 重新启动广播，等待下次连接
            advertising_start();
            break;

        case BLE_GATTS_EVT_WRITE:
            // 手机写入 UART RX 特征值 → 转发至串口
            if (p_ble_evt->evt.gatts_evt.params.write.handle ==
                m_uart_service.rx_handles.value_handle) {
                uint8_t  *data = p_ble_evt->evt.gatts_evt.params.write.data;
                uint16_t  len  = p_ble_evt->evt.gatts_evt.params.write.len;
                for (uint16_t i = 0; i < len; i++) {
                    app_uart_put(data[i]);   // 逐字节写入 UART TX FIFO
                }
            }
            break;

        default:
            break;
    }
}

主循环机制

程序采用裸机（无 RTOS）事件驱动架构，主循环简洁，所有处理均通过中断/回调驱动：

1
检查 UART 帧就绪标志 — 若 m_uart_frame_rdy == true，进入 UART→BLE 转发流程
2
读取环形缓冲区 — 取出最多 244 字节，构成一个 BLE 发送包
3
BLE 通知发送 — 若 BLE 已连接且 CCCD 使能，通过 sd_ble_gatts_hvx() 发送通知
4
UART 回显 — 将同一数据包通过 app_uart_put() 回写至 UART 输出
5
循环限流 — 每次主循环最多发送 10 包，超出则等待下次循环继续
6
电源管理 — 调用 nrf_pwr_mgmt_run()，无事件则 CPU 进入 WFE 低功耗等待
SoftDevice 事件（BLE / ANT）通过中断触发回调，UART 事件通过 ISR 写入环形缓冲区，主循环仅处理 UART→BLE 转发的批量数据路径，保持极低的 CPU 占用。

# user/pca10040/s312/armgcc/Makefile

PROJECT_NAME     := ble_ant_app_hrm_pca10040_s312
TARGETS          := nrf52832_xxaa
OUTPUT_DIRECTORY := _build

SDK_ROOT  := ../../../../..
PROJ_DIR  := ../../..

# SoftDevice 头文件路径（S312 双协议栈）
INC_FOLDERS += $(SDK_ROOT)/components/softdevice/s312/headers
INC_FOLDERS += $(SDK_ROOT)/components/softdevice/s312/headers/nrf52

# 编译标志
CFLAGS += -DBOARD_PCA10040
CFLAGS += -DCONFIG_GPIO_AS_PINRESET
CFLAGS += -DFLOAT_ABI_HARD
CFLAGS += -DNRF52832_XXAA
CFLAGS += -DS312
CFLAGS += -mcpu=cortex-m4
CFLAGS += -mfloat-abi=hard
CFLAGS += -mfpu=fpv4-sp-d16

# 链接 S312 SoftDevice 十六进制文件

内存布局（nRF52832-XXAA + S312）

区域起始地址大小用途
SoftDevice Flash0x00000000~152 KBS312 SoftDevice 代码（只读，烧录时合并）
应用 Flash0x00026000~360 KB用户应用代码及常量数据
FDS / NVMFlash 末尾~8 KB绑定配置持久化存储
SoftDevice RAM0x20000000~6 KBSoftDevice 运行时数据
应用 RAM0x20001800~58 KB用户代码栈、堆及全局变量
S312 SoftDevice 需要预留约 6 KB RAM（确切大小由 SoftDevice 版本决定）。修改 BLE 连接数或 ATT 表大小时，需同步调整 sdk_config.h 中的 RAM 起始地址，否则 SoftDevice 初始化会返回 NRF_ERROR_NO_MEM。

Git 提交与 BUG 修复历史

仓库最近三次提交均为 BLE-UART 双向转发链路的稳定性修复：

1
d30dd05 — 修复长时间不连接蓝牙会死机BUG （最新）
问题：设备在 BLE 长时间未连接状态下调用 sd_power_system_off() 进入系统关机， 导致无法再次广播，表现为设备"死机"或无响应。
修复：改为超时后重新调用 advertising_start() 并重启 ANT 信道， 保持设备持续可被发现，彻底解决长待机死机问题。
2
bb81dc7 — 修复ble与串口双向转发BUG
问题：BLE → UART 和 UART → BLE 两个方向的数据路径存在竞争条件， 导致部分数据丢失或乱序。
修复：重构数据转发逻辑，确保 BLE 写入事件的 UART 输出路径与 UART 接收缓冲区的 BLE 通知路径互不干扰，双向稳定工作。
3
a859f4a — ble转发串口有BUG （初始修复）
问题：BLE 转发至 UART 的方向存在 Bug，发现并记录了问题。
修复：初步修正了 BLE→UART 单方向的转发逻辑，作为后续完整修复的基础。
三次提交形成完整的 Bug 发现 → 局部修复 → 全面修复的闭环。当前主分支（main）已解决全部已知的 BLE/UART 双向转发和长待机死机问题，系统运行稳定。
