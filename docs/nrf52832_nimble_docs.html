Project Overview

NRF52832-NimBLE

基于 Nordic nRF52832 微控制器的 BLE 5.0 项目，集成 Apache NimBLE 完整协议栈（Host + Controller） 与 RT-Thread 4.0 实时操作系统，无需 SoftDevice 固件依赖，完整实现 GAP、GATT、SM 协议， 支持 Keil MDK5 和 GCC + SCons 双工具链编译。

Nordic nRF52832 Apache NimBLE RT-Thread 4.0 BLE 5.0 GAP · GATT · SM Keil MDK5 GCC + SCons 无 SoftDevice
协议栈: Apache NimBLE (Apache License 2.0)  ·  RTOS: RT-Thread 4.0.0  ·  芯片: Nordic nRF52832 (ARM Cortex-M4F)  ·  完整 Host + Controller 软件实现，不依赖 Nordic SoftDevice

RT-Thread 集成

RT-Thread 是一个开源、轻量级的实时操作系统，本项目使用 4.0.0 版本。

系统启动流程

1
Boot Code（汇编） — 设置栈指针，跳转到 C 启动代码
2
rt_hw_board_init() — 驱动初始化：os_tick_init()、rt_system_heap_init()、rt_components_board_init()
3
main() — 应用入口，初始化 NimBLE 和用户代码
4
rt_thread_idle() — 任务调度开始，NimBLE Host/Controller 线程运行

NimBLE 线程配置

线程名栈大小优先级职责
ble_hs1536 B6（中等）处理 GAP、GATT、SM 等高层协议
ble_ll1024 B7（较高）处理 Link Layer、PHY 等底层协议

内存管理

RT-Thread 使用 malloc-style 堆管理，堆范围从 BSS 段末尾到 0x20010000（RAM 末尾，64 KB 总容量）。NimBLE 数据包缓冲池通过 mbuf 机制动态分配。

GATT 服务设计

GATT（Generic Attribute Profile）是蓝牙的应用层接口，通过 Service 和 Characteristic 组织数据。

核心概念

Service（服务）
一组相关功能的集合，由 UUID 标识
Heart Rate Service (0x180D)
Battery Service (0x180F)
Custom Service（自定义 128-bit UUID）
Characteristic（特性）
Service 内的数据项，包含 Value（数据）、Properties（读/写/通知权限）、Descriptors（额外信息）

GATT 服务定义示例

#include "host/ble_hs.h"

/* GATT 服务和特性定义 */
static const struct ble_gatt_svc_def gatt_svcs[] = {
    {
        .type = BLE_GATT_SVC_TYPE_PRIMARY,
        .uuid = BLE_UUID16_DECLARE(0x180D),   /* Heart Rate Service */
        .characteristics = (struct ble_gatt_chr_def[]) {
            {
                .uuid      = BLE_UUID16_DECLARE(0x2A37),
                .access_cb = gatt_svr_chr_access,
                .flags     = BLE_GATT_CHR_F_READ | BLE_GATT_CHR_F_NOTIFY,
            },
            { .uuid = NULL }  /* 终止符 */
        }
    },
    { .type = BLE_GATT_SVC_TYPE_END }  /* 终止符 */
};

GAP 广播与连接

GAP（Generic Access Profile）处理设备发现和连接管理，定义了四个主要角色：

角色行为典型用途
Peripheral（外设）广播信号，接受连接传感器、手环等
Central（中心）扫描发现，主动连接手机、网关等
Broadcaster（广播者）仅广播，不接受连接Beacon 等
Observer（观察者）仅扫描，不连接数据采集器等

启动广播示例

static void start_advertising(void) {
    struct ble_gap_adv_params adv_params;
    struct ble_hs_adv_fields fields;

    /* 设置广告数据 */
    memset(&fields, 0, sizeof(fields));
    fields.flags             = BLE_HS_ADV_F_DISC_GEN | BLE_HS_ADV_F_BREDR_UNSUP;
    fields.name              = (uint8_t *)"MyDevice";
    fields.name_len          = strlen("MyDevice");
    fields.name_is_complete  = 1;

    ble_gap_adv_set_fields(&fields);

    /* 启动广播：通用可发现，永久广播 */
    memset(&adv_params, 0, sizeof(adv_params));
    adv_params.conn_mode = BLE_GAP_CONN_MODE_UND;
    adv_params.disc_mode = BLE_GAP_DISC_MODE_GEN;

    ble_gap_adv_start(BLE_OWN_ADDR_PUBLIC, NULL, BLE_HS_FOREVER,
                      &adv_params, gap_event_callback, NULL);
}

蓝牙 API 参考

核心初始化

函数说明
ble_hs_init()初始化 Host 栈
ble_hs_start()启动 Host
ble_hs_thread_startup()创建 Host 线程

GAP API

ble_gap_adv_start() — 启动 BLE 广播

原型：int ble_gap_adv_start(uint8_t own_addr_type, const ble_addr_t *direct_addr, int32_t duration_ms, const struct ble_gap_adv_params *adv_params, ble_gap_event_fn *cb, void *cb_arg)

返回值：0 = 成功，非 0 = 错误代码

ble_gap_disc() — 扫描 BLE 设备

作为 Central 角色发起扫描，发现周围的 Peripheral 设备

ble_gap_connect() — 发起连接

作为 Central 角色主动连接远端 Peripheral 设备

GATT Server API

函数说明
ble_gatts_add_svcs()添加 GATT 服务定义数组
ble_gatts_chr_updated()通知特性值已更改（触发 Notify/Indicate）
ble_gattc_notify_custom()发送 Notify（无需 ACK）
ble_gattc_indicate_custom()发送 Indicate（需要 ACK）

常见配置场景

增加最大连接数
修改 PKG_NIMBLE_MAX_CONNECTIONS 为 4，同时增加 Host 栈大小到 2048 字节
启用 Central 角色
确保 PKG_NIMBLE_ROLE_CENTRAL 启用，调用 ble_gap_disc() 扫描，ble_gap_connect() 连接目标设备
